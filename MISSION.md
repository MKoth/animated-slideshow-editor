# Mission: Understand the AnimatedSlidesRedactor Architecture

## Why
I need to fully understand this codebase — from folder structure to code-level decisions — so I can contribute features, fix bugs, plan refactors, and make informed architectural choices. The goal is deep comprehension, not surface familiarity.

## Success looks like
- I can navigate any part of the codebase and explain why it exists and how it connects to other parts
- I can trace a user action from the UI through the engine, commands, and persistence layers
- I can evaluate whether a proposed change fits the existing patterns or requires a new approach
- I can onboard others by explaining the architecture clearly

## Constraints
- I am a programmer; I know TypeScript, Python, React, and PixiJS. Skip language basics.
- Focus on architectural decisions, patterns, and the "why" — not syntax or APIs I can look up.

## Out of scope
- Re-teaching TypeScript, Python, React, or PixiJS fundamentals
- Line-by-line code walkthroughs of straightforward utility code
