Lesson 7

IK & Constraints

How bone chains reach targets and nodes obey behavioral rules.

Two Systems, One Pipeline

IK and constraints are separate systems that compose in the rendering pipeline:

Keyframe evaluation (per node) → IK solving (per chain, per slide) → Constraint evaluation (per node, per constraint) → Final world transform

Both are evaluated after standard keyframe animation and before the renderer applies the transform to Pixi containers.

Inverse Kinematics

The Problem

Forward kinematics: rotate the shoulder, then the elbow, then the wrist. The hand goes where the chain takes it. Inverse kinematics: specify where the hand should be, and the system figures out the shoulder and elbow rotations.

IKChain engine/ikChain.ts

An IK chain is a path of bone nodes from root to end effector:

class IKChain {
  id: string
  slideId: string          // IK is per-slide
  boneIds: string[]        // ancestor → descendant path
  target: BoneIKTarget     // where the end effector should reach
  poleTarget: PoleTarget | null  // optional elbow/knee direction
  ghostNodeId: string | null     // invisible helper node for target
}

interface BoneIKTarget {
  position: { x, y }      // world-space target
  nodeId?: string          // optional node to attach to
}

Validation: chain must have ≥2 bones, all must have bone component, and each must be a child of the previous (ancestor-descendant path).

Ghost Nodes

The IK target is anchored to a ghost node — an invisible scene node with the ghost component. This lets the user drag the target in the editor. The ghost node is created automatically when an IK chain is created.

Two-Bone Analytical Solver

Closed-form solution using the law of cosines:

// Given: bone1 position, target position, lengths L1, L2
dist = distance(bone1, target)
clamp dist to [minReach, maxReach]  // |L1 - L2| to L1 + L2

cosAngle1 = (L1² + dist² - L2²) / (2 * L1 * dist)
angle1 = acos(cosAngle1)

targetAngle = atan2(dy, dx)
bone1WorldRotation = targetAngle ± angle1  // sign from pole target
bone2WorldRotation = targetAngle - bone1WorldRotation

The pole target determines the sign (which side the elbow bends). If no pole target, defaults to positive.

CCD Solver (N-Bone)

Iterative algorithm, 10 iterations default, tolerance 0.001:

for each iteration:
  compute end effector position
  if dist < tolerance: break

  for i = last bone downto first bone:
    pivot = world position of bone i
    endVector = endEffector - pivot
    targetVector = target - pivot
    angle = atan2(cross(end, target), dot(end, target))
    clamp angle to ±0.5 rad per iteration
    rotations[i] += angle
Why clamp rotation per iteration? Without clamping, CCD can produce wild oscillations. The 0.5 rad limit ensures smooth convergence.

How IK Integrates with the Pipeline

The renderer's #handleTimeChanged() calls:

// 1. Compute IK overrides for all chains
transformSource.updateIKOverrides(slideId, time)

// 2. Apply IK rotations to containers
sceneRenderer.applyIKOverrides(rotations)

The EvaluatedWorldTransformSource in worldTransform.ts applies IK overrides when computing world transforms — overriding the rotation of bone nodes.

Constraints

Constraint engine/constraint.ts

Four constraint types, each with its own params:

TypeParamsEffect
rotationLimitminRotation, maxRotation (degrees)Clamps rotation to range
lookAttargetX, targetY, targetNodeId?Points rotation toward target
distancetargetNodeId, minDistance, maxDistanceClamps distance from target
parenttargetNodeId, position/rotation/scaleInfluenceFollows target with influence weights

Constraints have a priority (lower = applied first). Multiple constraints on one node are applied in priority order.

Which types require bone nodes? rotationLimit and lookAt require a bone component. distance and parent work on any node.

ConstraintEvaluator engine/constraintEvaluator.ts

Applied after IK, per node:

applyConstraints(worldTransform, constraints, context):
  result = { ...worldTransform }
  for each constraint (sorted by priority):
    result = applySingleConstraint(result, constraint, context)
  return result

Individual Constraint Logic

Rotation Limit

// Clamp world rotation to [min, max] (converted to radians)
rotation = clamp(world.rotation, minRad, maxRad)
return { ...world, rotation }

Look At

// Point rotation toward target position
dx = targetX - world.x
dy = targetY - world.y
rotation = atan2(dy, dx)
return { ...world, rotation }

If targetNodeId is provided, the target position comes from that node's world transform.

Distance

// Clamp distance from target to [min, max]
dist = distance(world, target)
if dist < minDistance: move to minDistance along angle
if dist > maxDistance: move to maxDistance along angle
return { ...world, x, y }

Parent Constraint

// Blend toward target with influence weights
x = world.x + (target.x - world.x) * positionInfluence
rotation = world.rotation + (target.rotation - world.rotation) * rotationInfluence
scaleX = world.scaleX + (target.scaleX - world.scaleX) * scaleInfluence
return { x, y, rotation, scaleX, scaleY }

Influence 0 = no effect. Influence 1 = fully follows target. 0.5 = halfway.

ConstraintManager engine/constraintManager.ts

Stores constraints per node, sorted by priority:

getConstraintsForNode(nodeId): Constraint[] {
  return ids.map(id => constraints.get(id))
            .sort((a, b) => a.priority - b.priority)
}

Constraints are removed when their node is deleted (removeConstraintsForNode).

How They Compose in the Renderer

Time changes → EvaluatedWorldTransformSource.updateIKOverrides(slideId, time) → For each IK chain: solve → store rotations → SceneRenderer.handleTimeChanged() → For each node: evaluateNode() → world transform → EvaluatedWorldTransformSource.transformOf(nodeId) → composeChain() with IK rotation overrides → applyConstraints() if any exist → Apply final transform to Pixi container

Key Design Decisions

  1. IK is per-slide. Different slides can have different IK configurations for the same bones.
  2. Ghost nodes for targets. IK targets are scene nodes — draggable in the editor, animatable in the timeline.
  3. Two solvers, automatic dispatch. 2-bone → analytical (exact, fast). N-bone → CCD (iterative, approximate). The system picks automatically.
  4. Constraints applied after IK. IK sets bone rotations, then constraints clamp/modify the result. Clear precedence.
  5. Priority-ordered constraints. Multiple constraints on one node apply in priority order. Lower number = first.
  6. Rotation limit is local-space. Applied in the renderer after IK overrides, before Pixi container update.
