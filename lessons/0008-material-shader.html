Lesson 8

Material & Shader System

How nodes get their visual appearance — from tint to custom GLSL.

The Definition/Instance Pattern

Like assets and clips, materials follow the definition/instance split:

ConceptLives inMutable?
MaterialDefinitionBackend library + embedded in projectNo (immutable)
MaterialInstanceEach SceneNodeYes (overrides)

A node doesn't own a material — it references a definition and carries overrides for specific parameters.

MaterialDefinition engine/materialDefinition.ts

21 lines. A frozen, reusable template:

class MaterialDefinition {
  readonly id: string
  readonly name: string
  readonly parameters: readonly MaterialParameterDefault[]  // parameter definitions
  readonly shaderId: string | null                           // optional GLSL shader
}

interface MaterialParameterDefault {
  key: string        // parameter name
  kind: string       // 'color' | 'number' | 'int' | 'bool' | 'vec2' | 'sampler2D'
  default: MaterialOverrideValue  // initial value
}

Every material definition carries two built-in parameters:

KeyKindDefaultEffect
tintcolor#ffffffColor multiply on the node's texture
opacityMultipliernumber1Multiplies with node opacity (0..1)

Additional parameters are custom shader uniforms defined by the material's GLSL shader.

MaterialInstance engine/materialInstance.ts

What each node carries:

interface MaterialInstance {
  materialDefinitionId: string    // reference to definition
  overrides: MaterialOverrides    // per-parameter value overrides
}

type MaterialOverrides = Readonly<Record<string, MaterialOverrideValue>>
type MaterialOverrideValue = string | number | boolean | readonly number[]

The default material is DEFAULT_MATERIAL_DEFINITION_ID with empty overrides (white tint, full opacity).

Resolution engine/materialResolution.ts

Given a definition's parameters and an instance's overrides, resolve the effective values:

resolveMaterial(parameters, overrides):
  tint = overrides.tint ?? definition.default.tint ?? '#ffffff'
  opacityMultiplier = clamp(overrides.opacityMultiplier ?? definition.default ?? 1, 0, 1)
  return { tint, opacityMultiplier }

resolveShaderUniforms(parameters, overrides):
  for each parameter (except built-ins and samplers):
    value = overrides[key] ?? parameter.default
    store as { key, kind, value }
  for each sampler2D parameter:
    store as { key, assetDefinitionId }
  return { source, keys, kinds, values, samplers, uTimeValue }
Override wins. Instance overrides always take precedence over definition defaults. If an override exists, the definition default is ignored for that parameter.

Material Animation

Material parameters can be animated via material tracks on nodes — same keyframe model as transform properties. The evaluator merges:

1. Static overrides (node.material.overrides)
2. Material track keyframes (animated at current time)
3. Clip material channel overrides (from clip instances)

Later layers win for the same key. Discrete kinds (int, bool, sampler2D) use hold interpolation; continuous kinds interpolate linearly.

ShaderDefinition engine/shaderDefinition.ts

14 lines. Holds the GLSL source and its uniform defaults:

class ShaderDefinition {
  readonly id: string
  readonly name: string
  readonly parameters: readonly MaterialParameterDefault[]  // uniform defaults
}

The GLSL source is stored in the backend library and resolved at render time via resolveShaderSource(shaderId).

Two Shader Levels

1. Per-Node Shaders

A material definition can reference a shaderId. When set, the renderer applies a Pixi filter to the node's placeholder container:

// In SceneRenderer.#applyNodeShader():
if (shaderSource) {
  filter = createNodeShaderFilter(pixi, programCache, source, scratch)
  applyFilterUniforms(filter, scratch)
  bindFilterSamplers(filter, samplers, resolveAssetUrl, textureCache)
  placeholder.filters = [filter]
}

The shader receives uniforms from the material definition + overrides + animation. The uTime uniform is automatically injected if the shader declares it.

2. Fullscreen Shaders

A slide can reference a fullscreen shader that processes the entire scene:

// In FullscreenPass:
1. Render scene to offscreen RenderTexture
2. Create fullscreen quad sampling that texture as uTexture
3. Apply shader filter to the quad
4. Quad composites to canvas

Fullscreen shaders receive:

  • uTexture — the rendered scene (reserved, built-in)
  • uTime — slide playhead time (reserved, built-in)
  • Custom uniforms from the shader definition + slide overrides
Scene renders to offscreen texture → Fullscreen quad samples texture as uTexture → Shader filter applies GLSL effects → Result composites to canvas

Sampler Binding pixi/renderer/samplerBinding.ts

Shader uniforms of kind sampler2D are bound to asset textures:

interface ShaderSamplerBinding {
  key: string                    // uniform name (e.g. 'uDiffuse')
  assetDefinitionId: string | null  // asset to sample
}

The sampler binding resolves the asset definition ID to a texture via the TextureCache, then binds it to the filter's texture resource.

Resolution in the Renderer

On every evaluation, the renderer resolves both material and shader:

#evaluateAndApply(nodeId):
  // Material
  overrides = engine.evaluateMaterialOverrides(nodeId, time)
  material = resolveMaterial(definition.parameters, overrides)
  
  // Shader
  resolveShader(definition.parameters, overrides, time, shaderScratch)
  shaderChanged = applyNodeShader(nodeId, container, shaderScratch)
  
  // Apply if changed
  if (materialChanged) applyMaterialTint(container, material.tint)
  if (stateChanged) applyEvaluatedState(container, state, material.opacityMultiplier)

Key Design Decisions

  1. Definition/instance separation. Shared definitions, per-node overrides. Changing a definition affects all referencing nodes.
  2. Built-in parameters. tint and opacityMultiplier are always available, even without a custom shader.
  3. Override wins. Instance overrides always take precedence over definition defaults.
  4. Two shader levels. Per-node (filter on one container) and fullscreen (post-processing over entire scene).
  5. Reserved uniforms. uTexture (scene texture) and uTime (playhead) are built-in. Authors cannot define conflicting defaults.
  6. Material animation. Same keyframe model as transforms — animate any material parameter over time.
  7. Sampler2D → asset texture. Shader uniforms can reference asset definitions, resolved at render time.
