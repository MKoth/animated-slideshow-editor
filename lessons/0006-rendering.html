The Rendering Pipeline

How the Pixi.js renderer maps engine nodes to containers and visualizes the scene.

The Architecture

The renderer is a pure consumer of engine events. It never mutates the engine. It subscribes, reacts, and updates Pixi containers accordingly.

Engine fires events via EventBus │ Renderer subscribes, selectively updates Pixi containers │ SceneRenderer maps node IDs → Pixi Containers │ Pixi.js renders to canvas (WebGL/WebGPU)

The Tick Loop

Every frame, Pixi's ticker calls #applyTick():

#applyTick() {
  // 1. Compute camera transform (from camera node or animation)
  const transform = this.#cameraTransform()

  // 2. Apply camera to world container (pan + zoom)
  camera.apply(transform)

  // 3. Update grid (colors, zoom, position)
  grid.update({ cameraX, cameraY, zoomX, zoomY, ... })

  // 4. Render fullscreen shader pass
  fullscreenPass.renderFrame()

  // 5. Update dev overlay (FPS, node count)
  devOverlay.update({ fps, cameraX, cameraY, zoom, nodeCount })
}

The Camera pixi/renderer/camera.ts

22 lines. Applies the viewport transform to the world container:

apply(transform) {
  world.position.set(-x * scaleX, -y * scaleY)
  world.scale.set(scaleX, scaleY)
}

The camera reads from the engine's camera node. If animation mode is on, it evaluates the camera's animated transform at the current time.

SceneRenderer pixi/renderer/sceneRenderer.ts

The core mapping layer. 859 lines. Maintains:

#containers: Map<string, PixiContainer>   // node ID → Pixi container
#nodeIds: WeakMap<PixiContainer, string>  // reverse lookup
#sizes: Map<string, WorldSize>            // node ID → bounding box
#lastEvaluated: Map<string, EvaluatedNodeScratch>  // previous state (change detection)
#lastMaterials: Map<string, EffectiveMaterialScratch>

Binding a Scene

When the active slide changes, bind() destroys all containers and rebuilds:

bind(scene, slideId) {
  // Destroy all existing containers
  for (container of #containers.values()) container.destroy({ children: true })
  #containers.clear()

  // Walk the engine tree, create a Pixi container per node
  for (node of walkPreOrder(scene.root)) {
    this.#addNode(node)
  }
}

Creating Node Containers

createNodeContainer() in nodeRenderer.ts creates a Pixi container with a placeholder child based on the node's component type:

ComponentPlaceholder
assetInstanceTexture sprite (loaded async)
textText sprite
boneLine + circles (red)
meshDeformable mesh display
tableTable container with cells
chartChart container
ghostInvisible (no placeholder)
Placeholder pattern: The container itself holds transform + opacity. The placeholder child holds the visual content. This separation lets the renderer update transform independently of content.

Evaluation Pipeline

On every relevant event, #evaluateAndApply(nodeId) runs:

1. engine.evaluateNode(nodeId, time) → EvaluatedNodeState 2. engine.evaluateMaterialOverrides() → MaterialOverrides 3. resolveMaterial(overrides) → { tint, opacityMultiplier } 4. resolveShader(overrides, time) → { source, uniforms } 5. Compare with lastEvaluated/lastMaterials (change detection) 6. If changed: applyEvaluatedState(container, state, opacity) 7. If material changed: applyMaterialTint(container, tint) 8. Store current state for next comparison

This is selective — only changed nodes are re-evaluated and re-rendered.

Time Changes Are Special

When the playhead moves, every node must be re-evaluated (animation). This is the expensive path. The renderer also updates IK overrides, constraint overrides, deformed mesh sizes, and the fullscreen shader.

Change Detection

The renderer avoids unnecessary Pixi updates by comparing with the previous state:

const stateChanged = !previous || !evaluatedStatesEqual(previous, state)
const materialChanged = !previousMaterial || tint/opacity changed

if (!stateChanged && !materialChanged && !shaderChanged) {
  return  // skip — nothing to update
}

This is critical for performance — Pixi container property sets trigger re-rendering, so avoiding no-op updates saves GPU work.

The Full Stack

User drags node on canvas → CanvasSelection detects mouseup → dispatch(MoveNodeCommand) → command.execute: engine.setTransform(...) → engine fires TransformChanged event → Renderer.#handleEvent(event) → sceneRenderer.handleTransformChanged(nodeId) → #evaluateAndApply(nodeId) → engine.evaluateNode(nodeId, time) → compare with lastEvaluated → if changed: applyEvaluatedState(container, state) → container.position.set(x, y) → container.rotation = rotation → container.scale.set(scaleX, scaleY) → selectionOverlay.redraw() → Pixi ticker fires → #applyTick() → camera.apply(transform) // viewport pan/zoom → grid.update(...) → app.renderer.render(...) → Canvas shows updated position

Key Design Decisions

  1. Renderer is a pure consumer. Subscribes to events, never mutates engine. Clean separation.
  2. Placeholder pattern. Container = transform. Placeholder child = visual content. Independent updates.
  3. Selective updates. Only changed nodes are re-evaluated. Time changes are the exception (all nodes).
  4. Change detection. Compare with previous state before updating Pixi properties. Avoids no-op GPU work.
  5. 40 renderer files. Each overlay/interaction is isolated. Easy to add new editing modes without touching the core.
  6. Texture + shader caches. Avoid re-loading and re-compiling. Cache invalidation is explicit.
