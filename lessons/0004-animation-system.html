Lesson 4

The Animation System

Keyframes, interpolation, evaluation, and the clip composition layer.

The Six Channels

Every node can animate exactly six properties:

PropertyTypeConstraint
positionXnumber (px)—
positionYnumber (px)—
rotationnumber (radians)Camera: locked, not animatable
scaleXnumber (multiplier)—
scaleYnumber (multiplier)—
opacitynumber (0..1)Bone: not animatable

Beyond these six, nodes can also animate material parameters (tint, shader uniforms) via material tracks. Same keyframe model, different namespace.

Keyframe engine/keyframe.ts

The atomic unit of animation:

class Keyframe {
  id: string
  time: number                    // seconds (0..slide.duration)
  value: KeyframeValue            // number | string | boolean | number[]
  interpolation: InterpolationType
  tangentIn:  { time: number, value: number }  // bezier control point
  tangentOut: { time: number, value: number }  // bezier control point
}

Keyframes on a track are sorted by time (insertion-sorted). Times must be monotonically increasing; duplicates only at the slide's duration boundary.

Interpolation Types

Six types, registered on a pluggable interpolator registry:

Constant
  • hold — value stays constant until next keyframe
Linear
  • linear — straight line between values
Parametric (easing)
  • bounce — decaying bounce effect
  • elastic — oscillating decay
  • spring — damped oscillation

Bezier Interpolation

The bezier type uses cubic bezier through the keyframe's tangent control points. The curve time is solved analytically via Cardano's formula — no iterative sampling, fully deterministic:

// Control points: from + tangentOut, to + tangentIn
// Solve x(u) = ratio for u, then evaluate y(u)
u = cubicRootInUnitInterval(x1, x2, ratio)
value = (1-u)³·v0 + 3(1-u)²u·v1 + 3(1-u)u²·v2 + u³·v3
Design decision: Parametric types (bounce, elastic, spring) are registered as segment interpolators that apply an easing function to the linear ratio. They're rejected on discrete material kinds (int, bool, sampler2D) — those only support hold.

Pluggable Registry

// Register a new interpolator
registerSegmentInterpolator('myEasing', (from, to, time) => { ... })

// Evaluation dispatches by name
evaluateSegment(from, to, time)  // looks up from.interpolation in registry

This is open for extension without modifying evaluation logic.

NodeAnimation engine/nodeAnimation.ts

Per-node animation data, stored in the SlideAnimation:

class NodeAnimation {
  #tracks: Map<AnimationProperty, Keyframe[]>        // positionX → [kf, kf, ...]
  #materialTracks: Map<string, Keyframe[]>            // "tint" → [kf, kf, ...]

  keyframes(property): readonly Keyframe[]
  materialKeyframes(parameter): readonly Keyframe[]
  add(property, keyframe)          // insert-sorted
  remove(property, keyframeId)
}

Tracks are sparse — only properties with at least one keyframe exist in the map. A node with no animation has no NodeAnimation entry at all.

The Evaluator engine/animationEvaluator.ts

The heart of the system. Given a node ID and a time, returns the evaluated state:

evaluateNode(nodeId, time): EvaluatedNodeState {
  // 1. Get the node's static transform as fallback
  // 2. For each of the 6 properties:
  //    - Find surrounding keyframes on the track
  //    - If no keyframes → use static value
  //    - If before first → use first value
  //    - If after last → use last value
  //    - If between → evaluateSegment(from, to, time)
  // 3. Apply clip instances (layered on top)
  // 4. Return { transform, opacity }
}
Static transform (fallback) → Keyframe evaluation (per channel) → Clip instance layering (per instance, per channel) → Final evaluated state

Clip Evaluation

For each clip instance on a node:

u = (time - instance.startTime) * instance.speed / clip.duration
u = clamp(u, 0, 1)  // normalized time within the clip

for each channel in clip:
  kfValue = evaluateClipChannel(channel.keyframes, u)

  if channel is linked to a param:
    paramValue = instance.paramOverrides[param.key] ?? param.default
    if linkMode == 'gain':   output = base * (paramValue * kfValue)
    if linkMode == 'offset': output = base + paramValue * kfValue
  else:
    output = kfValue

  setChannelValue(state, channel.property, output)
Composition order: Base keyframes → material tracks → clip instances. Each layer overwrites the previous. Clips that haven't started yet (time < startTime) don't contribute.

The Clip System

ClipDefinition engine/clipDefinition.ts

A reusable, parameterized animation template:

class ClipDefinition {
  id: string
  name: string
  duration: number           // in seconds
  category: string           // for organization
  params: ClipParam[]        // user-adjustable scalars
  channels: ClipChannelDef[] // which properties it animates
  channelAnimations: Map<property, ClipChannelAnimation>
  materialChannelAnimations: Map<paramKey, ClipChannelAnimation>
}

Clip keyframes use normalized time [0, 1], not absolute seconds. The clip's duration maps 0→1 to the actual time range.

ClipParam

interface ClipParam {
  key: string       // unique identifier
  label: string     // display name
  kind: 'number' | 'color' | 'vec2'
  default: number   // initial value
}

ClipChannelDef

interface ClipChannelDef {
  property: AnimationProperty   // which of the 6 channels
  paramKey?: string             // link to a param (optional)
  linkMode?: 'gain' | 'offset'  // how param combines with base
  materialParameter?: string    // target a material param instead
}

ClipInstance engine/clipInstance.ts

A node's reference to a clip, with timing and overrides:

interface ClipInstance {
  id: string
  clipId: string
  startTime: number              // when it starts (seconds)
  speed: number                  // playback speed multiplier
  enabled: boolean
  paramOverrides: Record<string, number>  // per-instance param values
}



Multiple clip instances can be layered on one node. They evaluate in order; later instances overwrite earlier ones on the same channel.



Easing Presets



The easingPresets.ts file maps named presets (Ease In, Ease Out, etc.) to bezier tangent configurations. These are convenience wrappers — the interpolator sees only bezier with specific tangent values.



Key Design Decisions



    
  
  1. Six channels, not arbitrary. The engine animates transform + opacity. Material parameters are the extension point for everything else.
    2. 
  
  2. Normalized clip time. Clips are time-agnostic templates. The instance's startTime and speed map them to absolute time.
    3. 
  
  3. Analytic bezier. Cardano's formula for cubic root solving — deterministic, no sampling, no approximation error.
    4. 
  
  4. Pluggable interpolators. New curve types register on the registry. Evaluation logic never changes.
    5. 
  
  5. Composition layers. Static → keyframes → material tracks → clips. Each layer overwrites. Clear, predictable precedence.
    6. 
  
  6. Scratch objects. The evaluator uses pre-allocated scratch targets to avoid allocation in hot loops.
